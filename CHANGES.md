### App
- Fixed Pushback on Beacon and on Final LS Options to be interlinked
- Changed Behavior of Arrival Gate (Pre) Selection in the UI
  - The entered Text is no longer 'normalized' and is now saved as it was entered (i.e. 'Gate' is not forcefully added anymore)
  - An optional Label (like "Gate", "Ramp", ...) that can be added as Prefix through a Dropdown (just a Shortcut to select instead of type) 
  - The App will still try the normalized Name for the gate.select API Method (but uses the Name as entered - including Label - for the menu.search Method)
- Fixed Push Direction (Pre) Selection in the UI to be disabled when Pushback is disabled in the GSX Profile or when no Directions are configured
- Fixed Push Direction (Pre) Selection to be disabled in Pushback Phase (but GSX Pushback is not yet commenced)
- Added automatic Handling of the 'Interrupt Pushback' Menu to select the Direction Selection if present
  - Only if no Direction was selected yet and no Command/Sequence is active (i.e. automatic Reopen)
  - Selection is linked to the existing Setting to reopen the Pushback Direction Menu
- Added Live Weights to the Flight Briefing View
- Fixed HasOpenDoor/CloseAllDoor Check on SessionStart not being triggered if Jetway or Stairs Services were active
  - Now filters for Services actually requiring an Aircraft Door
  - After that the App will still Check if Doors for Jetway/Stairs need to be opened
- Changed the Service Dependent Cancellation to only trigger after the Service reached at least the Active State
- Added a minimum Run Time Parameter for Service Dependent Cancellation - only canceling the Service after that Time has passed (since becoming Active)
- Improved Startup Time when the Session starts
- Restructered all of the Automation Controller (Phases, SmartButton) and overhauled Walkaround Handling
  - The Preparation Phase now starts already in 'Ready to Fly' Screen regardless if the App or Sim is configured to Skip the Walkaround or not
  - Services like Reposition, Jetway (not in Walkaround), Stairs and Ground-Equipment are already called there
  - Ground-Equipment is only placed when the Aircraft can already connect in that Phase
  - The Option to Connect Stairs (and Reposition) while in Walkaround was thus renamed as it applies to both Walkaround/'Ready to Fly' (and is decoupled from the Walkaround Skip Option)
  - Added a Sub-Option to prefer the Aircraft's custom Stairs if the Walkaround Mode is active (not skipped in the Sim)
  - Accordingly a new Option was added to control if the Ground-Equipment should also be handled that soon (defaulting to on)
- Removed Option to refresh GSX Simbrief/VDGS on Turnaround (the Departure Option handles both Cases)
- Changed Text and Tooltip for the Jetway/Stair when Departure Services Option to better reflect this is constantly monitored (not only checked once)
- Changed Text and Tooltip for the Jetway/Stair on Session Start Option for better Distinction to the other Options
- Changed Behaviour for Menu Sequences (i.e. Service Calls) always open the Menu (not using an already opened Menu) and failed Sequences have additional Delay
- Fixed Remove Stair Question being answered when Automation is disabled
- Fixed Operate Jetway Notification not disappearing
- Added Support for the Airstair Question/System
  - Added Option in Door Handling to prefer Airstairs over GSX Jetway/Stairs, applying to all other Options concerning Stairs connecting or removing Stairs
  - If enabled the Airstair Question will be answered with 'Both' to trigger both Airstairs & GSX Stairs for the configured Exits
  - If disabled (default) the Airstair Question will be answered with 'No' using GSX Jetway/Stairs normally (and not operating the Airstairs)
  - If the Aircraft has Airstairs and if they are extended, they will be removed regardless of Setting when Stairs in general are about to be removed
- Fixed Flight Briefing showing OUT and TTD after Departure
- Changed App Monitor to check for Audio Controller State and Avionics Powered (so if the Audio Control is truly active)
- Changed Error Message on enabling Remote Control Server to only display when the API was never connected (while the App is running)
- Improved GSX Service State Handling
  - Service States Variables are actively reset by the App when it detects a GSX Restart/Disconnect
  - Vehicle States are always checked (and corrected if needed) when ever the App's Service State is reset 
  - Changed the Stair Service to mostly rely on the Vehicle State as Service and Operating State can go MIA
  - Prevent State Notification when GSX API is not ready (to accommodate the changed Startup Behaviour)
  - Restarting GSX through the App (i.e. Sys-Tray, Startup, Taxi-In) now does a preventive reset of the Service and Vehicle State Variables
- Changed the Effect of the call Jetway/Stairs on Arrival Option when used together with running Departure Services during Deboard
  - Jetway/Stairs are constantly monitored (not only checked once) in this Situation
  - For Example Stairs disconnected because of other Services will already re-connect during Boarding
- Improved the Stair Conflict Handling
- Fixed Dropdown Items and Order for the Sevice Door Mappings
- Fixed Menu Refresh for PilotsDeck or EFB to be triggered during Engine start (i.e. Parkings with direct Taxi-Out)
- Improved Lua Error Logging further
- Improved Messages in UI / Notifications to differentiate between Refuel and Defuel
- Updated .NET Packages

### Plugin Interface
- Added Lua Globals for Weight Conversion: WeightToLb and WeightToKg
- Added Lua Globals to de-/serialize Json: ToJsonString and ToJsonNode (which deserializes to a LuaTable)
- Added common Enums as Lua Globals - i.e. using AircraftDoor.L1 or GsxDoor.PaxDoor1 for Comparisons in Lua
  - In addition to this the C# to Lua Method Calls explicitly converts the passed (Enum) Parameters so that they are treated as number in Lua
- Removed the IsConnected Property in the Aircraft Base and replaced it with a GetIsConnected Method (overridable in Lua)
- Added Methods to handle Aircraft Custom Stairs: HasCustomStairs, GetCustomStairsFront/Rear, SetCustomStairsFront/Rear
- Added Plugin Capability HasCustomStairs to indicate custom Stair Handling in Plugin Notes and Gate & Doors Control
- Changed Behaviour when the BeforeWalkaroundSkip and AfterWalkaroundSkip Methods are called
  - Both Methods are only tried once before or after Walkaround / Ready to Fly Mode and only if the Aircraft is already connected
- Changed Behaviour of the HandleWalkaroundEquipment Method: it is called regulary in the Walkaround / Ready to Fly Mode, even when the Aircraft is not connected! (But only if the User configured PlaceGroundEquipWalkaround)
- Changed UpdatePassengerCount Method in Flightplan Interface to directly update the GSX Boarding Target
- Changed Behaviour of the GetHasAirStairX Methods: They are now used to determine if an Airstair is generally available (so not retracted or extended State)
- Added Methods GetAirStairX and SetAirStairX to actually get and set the State of the Airstair
- Changed the DoorsAllClose Method to be not overridable to ensure consistent Behaviour
  - The Airstairs are considered Doors and thus are included in the Method
  - Plugins should now use the new Method CloseAllCustomDoors to close additional Doors (which is called at the End of DoorsAllClose)
- Added Plugin Capability HasAirStairs to indicate Airstair Handling in Plugin Notes and Gate & Doors Control
- The Lua Global ToggleWalkaround was removed
- Added Value 'None' (-1) to the AircraftDoor Enum to indicate that this Door is not existent / used
- Changed the MapDoorDefaults Method to also return a default Mapping for Cargo and changed the Pax-Mapping to L3 being None
- Changed Methods for Stair & Jetway Calls in AircraftController to also check the PluginCapabilities (i.e. differentiate if PaxJetway and/or PaxStairs are synced)
- Updated .NET Packages
